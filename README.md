2. El modelo MTV es el que utiliza Django, M (model) es la capa donde se encarga de comunicar e interactuar con la base de datos, T (template) que se encarga de mostrar los datos de los usuarios, y la V (view) la capa donde se maneja la logica de la pagina. A diferencia del modelo MVC, que el el moodelo en el que se basa el MTV, el cambio varia principalmente el el nombre de cada capa, en MVC seria M(model) igual al MTV, V (view) seria el template y la C (controller) seria como la view. La diferencia ademas del cambio de cada modelo seria que MTV esta mas enfocado en la rapidez de entrega de la respuesta renderizada al usuario, ya que el modelo MVC funciona un poco mas lento en paginas de gran cantidad de usuarios ("https://www.desarrollolibre.net/blog/django/el-patron-de-diseno-mtv-en-django-y-su-relacion-con-el-mvc")

El flujo request-response en django es la manera que tiene de comunicarse entre el usuario y el servidor web, se relaciona con el modelo MTV, de esta manera empieza cuando el usuario hace una peticion http en la pagina web, un archivo urls.py recibe la peticion y la deriva a la view, la view interactua con el model y luego la view toma los datos y envia la respuesta ("https://developer.mozilla.org/es/docs/Learn_web_development/Extensions/Server-side/Django/Introduction")
5. El ORM convierte la estructura tradicional de la base de datos en clases en python, facilitando el trabajo en python. de esta manera se puede guardar informacion en una base de datos utilizando clases de python ("https://aws.amazon.com/es/what-is/object-relational-mapping/")
6. las plantillas en django permite separar la parte visual de la estructura del codigo, una plantilla contiene el resultado HTML, de esta manera el codigo queda mas limpio y es mas facil trabajarlo en python ya que no se mezcla con codigo HTML ("https://blog.jetbrains.com/es/pycharm/2025/06/la-guia-definitiva-de-las-plantillas-de-django/")
